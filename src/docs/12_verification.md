# 12. 검증 기록 (Verification Record)

이 문서는 **배포본에 남기는 검증 증거의 요약**이다. 이 시스템이 어떻게 검증됐고,
무엇이 확인됐으며, 무엇이 검증 밖에 있는지를 배포 리포 이력에 명시적으로 남긴다.

상세한 세션별 감사 이력(발견·근거·소유자 판단)은 저장소 밖 워킹 아카이브
`audit/`(git 제외)에 보관한다. 이 문서는 그중 **오래갈 결론만** 정제한 것이다.

> **이 문서의 성격**: 여기 담긴 것은 **공학적 증거**(테스트 통과 + 변이 검사)이지,
> 법적 안전성의 **인증**이 아니다. "입력·설정 오류가 없다면 계산·통제 로직이 규칙대로
> 동작함을 강하게 뒷받침한다"까지가 이 기록의 주장이며, 릴리즈 가부와 법적 판단은
> 이 증거를 근거로 소유자·기관이 내린다.

기준 시점: v0.2.6 (`Cargo.toml`), 백엔드 로직 동결 상태. 최종 갱신 2026-07-23.

## 1. 검증 방법론 — 변이 검사(mutation testing)

"테스트가 있다"와 "테스트가 오류를 잡는다"는 다르다. 함수를 호출만 하고 결과를
단언하지 않는 테스트, 항상 참인 단언, 상태 코드만 보는 거부 테스트는 초록을 내면서도
아무것도 지키지 못한다.

그래서 핵심 로직은 **일부러 결과가 틀리게 망가뜨려**(예: 부등호 뒤집기, 정렬 방향
반전, 합산을 뺄셈으로, 정원 비교 off-by-one) `cargo test --all`을 돌리고, **반드시
어떤 테스트가 실패하는지** 확인했다. 실패하지 않으면 그 테스트는 그 오류를 막지
못하는 것이므로 테스트를 보강했다.

**변이 검사의 한계(정직하게)**: 이 방법은 "주입한 이 오염들을 테스트가 잡는다"를
증명하지, "가능한 모든 버그가 없다"를 증명하지 않는다. 형식 검증(formal verification)이
아니다. 다만 각 계산·통제 로직의 핵심 분기를 체계적으로 훑어 주입했다.

## 2. 현재 검증 상태

> **측정 수치는 적지 않는다.** 테스트 개수·함수 개수·변이 건수 같은 값은 커밋 한 번에
> 낡는다. 이 문서는 그 수치로 세 번 틀렸다. 대신 **재현 명령**을 적는다 — 읽는 사람이
> 지금 값을 직접 얻는 쪽이 언제나 옳다. (CLAUDE.md 규칙 9)

- **백엔드 전량 통과, 실패 0.**

  ```
  cargo test --all
  ```

  doc-test 는 없다. `npm run ci` 로그의 합계는 이 명령보다 크게 나오는데, 오라클
  단계가 `cargo test --test audit_oracle_dump` 를 한 번 더 돌려 겹치기 때문이다 —
  기준은 `cargo test --all` 이다.

- **프론트엔드 전량 통과.**

  ```
  npm --prefix frontend test
  ```

- **변이 검사: 계산·통제 계열 전량 검출, 방어 공백 0.**
  - 계산 계열: 점수 산출(구간 UPPER/LOWER/EXACT 매칭·범주 SUM/MAX·만점 캡·총점
    합산), 순위·재학생 우선 정렬·동점 처리, 정원·초과추천, 잔여석·추천 가능 인원 산술.
  - 통제 계열: 관리자 권한 경계(담임→관리자 승격 차단), 라운드 상태 전이
    (마감·재오픈·CLOSED 전용 추천/계산), 추천–미선발 배타, 미결정자 마감 차단.

- **공개 함수 커버리지**: 이름으로 참조되지 않는 공개 함수는 Win32 `extern` 과,
  간접 호출·변이로 커버가 확인된 것뿐이다. 실제 미검증 0.
  목록을 다시 뽑으려면 `git grep -nE "^\s*pub (async )?fn " -- src/`.

### Float-Free — 계산이 정수 정확인 이유

모든 점수는 ×100000 정수(`Score` newtype)로 저장·합산·비교된다. 합산은 정수
`checked_add`(오버플로는 조용히 wrap하지 않고 오류), 순위는 SQL 정수 `RANK()`.
부동소수점은 **입력 파싱**(가드: 유한·±10억 이하·소수 5자리 이하 → 이 도메인에서
`(f×100000).round()`가 항상 정확한 정수)과 **표시 출력**(÷100000) 두 경계에만 닿는다.

## 3. 실수 → 계산 오류 차단 (관리자·담임 실수 방어)

관리자·담임의 실수가 계산을 오염시키는 경로는 즉시 차단되며, 각 가드에 테스트가 있다.
**단순 입력값 오타·설정 판단 오류는 시스템이 알 수 없어 차단 대상이 아니다**(범위 밖).

| 실수 | 차단 |
|---|---|
| 점수표 단조성 위반(UPPER인데 점수 역전) | 오류, 저장 안 됨 |
| 점수·값이 만점 초과 | 오류 |
| 양수 점수 그룹에 0점 기준 누락 | 오류 |
| 임계값·범주 중복 등록 | 오류(마지막이 조용히 이기지 않음) |
| 미등록 학생의 기초데이터 업로드 | 422, 전체 롤백 |
| 마감된 라운드의 점수 기준 변경 | 409, 기준표 불변 |
| 마감 라운드 지원자의 재학/졸업 전환 | 거부(순위 기준 어긋남 방지) |
| 정원 초과 추천 / 순위 건너뛴 추천 | 409 |
| 미결정자 남긴 채 라운드 확정 | 422 |
| 점수 기준표·데이터 없이 계산 | **명시적 `Err` — 조용한 0점 아님** |
| NaN·무한대·지수표기·소수 6자리·10억 초과 입력 | 파싱 거부 |

마지막 두 줄이 특히 중요하다 — "실수가 조용한 오류로 남는" 최악의 경우를 막는다.

## 5. 검증 밖 (명시적 한계)

아래는 이 기록이 **보증하지 않는** 영역이다.

- **입력값 오타**: 담임이 58을 85로 입력 — 유효 범위의 값이라 시스템이 알 수 없다.
- **설정 판단 오류**: 관리자가 만점·정원·점수표 값을 의도와 다르게 설정 — 값 자체는
  규칙에 맞으므로 로직 오류가 아니다.
- **프론트엔드 렌더링(외관)**: 자동화 테스트 없음(육안 확인 영역). 레이아웃·페인트
  문제는 사람이 화면을 열어야 드러난다(13_frontend_pitfalls.md).
  자동 검증되는 것은 다섯이다. ① **템플릿의 미정의 식별자** —
  `frontend/tests/undefined-identifiers.test.js` 가 `.vue` 전 파일을 컴파일해
  템플릿이 참조하는 이름 중 정의가 없는 것을 찾는다(실행하지 않으므로 `v-if` 뒤도 본다).
  ② **"열리기는 하는가"** — `frontend/tests/smoke-render.test.js` 가 모든 화면을
  마운트하고, [라운드]·[담임 지원 등록] 은 눌러서 표·패널까지 연다(2026-09-21 도입).
  미정의 식별자로 화면이 아예 열리지 않던 사고(§13-4)가 그 계기다.
  ③ **되돌리기 어려운 행위의 확인 절차** — `dialog.render.test.js`(2단계 확인·ESC·
  동시 호출)와 `destructive-confirm.test.js`(danger 확인을 쓰는 **모든 버튼**을 실제로 눌러
  ① danger 다이얼로그가 뜨는지 ② **취소하면 서버 호출이 일어나지 않는지**를 본다).
  ②가 핵심이다 — 다이얼로그가 뜨는 것만 보던 동안, 확인 결과를 무시하는 회귀
  (취소해도 삭제)가 전 검증을 통과했다.
  ④ **정원 입력이 값을 조용히 바꾸지 않는가**(F-013) —
  `frontend/tests/quota-input.render.test.js`. 네 폼을 열고 **렌더된 number 입력칸을
  전부** 훑어, 0 을 넣었을 때 화면의 어떤 저장 버튼도 열려 있지 않은지 본다.
  소스에서 `<QuotaInput>` 개수를 세던 판은 **공용 컴포넌트를 안 쓰는 폼**을 놓쳤다 —
  그것이 F-013 의 실제 재발 경로다.
  ⑤ **화면에 null/undefined/NaN 이 글자로 새어 나오는가** — 스모크가 함께 본다.
  잡지 못하는 것: 클릭해야 도달하는 **핸들러 본문**의 오류, 픽스처가 도달시키지
  못하는 화면 영역, 스크립트 본문의 미정의 식별자 중 마운트 경로 밖의 것.

  그리고 **`.vue` 밖으로 빼낸 일부 파생 로직**: `src/logic`·`src/utils`·
  `src/data`의 순수 모듈은 `vitest`가 직접 호출해 검사하고(2026-09-21 도입), 점수
  표기·동점 표식·재정렬은 `tools/oracle/front_check.mjs`가 백엔드 실측값과 대조한다.
  **범위를 정직하게 적는다**: 추출된 것은 `.vue` 안 `computed` 의 **일부**이고,
  나머지 대다수는 여전히 육안 확인 영역이다. 비율을 숫자로 적지 않는 이유는
  CLAUDE.md 규칙 9 — 앞서 두 번 적었고 두 번 다 다음 커밋에서 낡았다.
  지금 범위를 알고 싶으면 `frontend/src/logic` 을 열어 보는 쪽이 정확하다.
  그리고 프론트는 점수를 계산하지 않고 표시만 하며(규칙 1), 표시 정밀도는 백엔드
  값과 일치한다.
- **동시성**: 실제 `BEGIN IMMEDIATE`·유니크 인덱스가 방어선이고 병렬 테스트가 있으나,
  전 경로 경합의 완전 증명은 아니다.
- **형식 검증 미수행**: "모든 경계·예외 조건"의 수학적 보장이 아니라, 체계적으로
  주입한 변이가 잡힌다는 증거다.
